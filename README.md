# DSCI 522: Titanic Survival Prediction

## Authors

Tahir Hussain, Jaylon Huang, Rakshit Kapoor, and Teeba Obaid

## Summary

This project investigates whether passenger information can predict survival on the Titanic. Using the Kaggle Titanic dataset (891 labelled training passengers and 418 unlabelled test passengers), we conduct exploratory data analysis, engineer domain-informed features, and evaluate regularized logistic regression models. The labelled training data is divided into a development set (70%, 623 passengers) and a held-out test set (30%, 268 passengers) using stratified sampling. Five-fold stratified cross-validation on the development set gives a mean accuracy of 77.8% for the five-feature logistic regression model and 82.2% for the extended model. The extended model achieves 84.3% accuracy and an F1 score of 0.784 on the held-out test set. We interpret observed patterns as associations in this historical dataset, not as evidence of cause and effect or as a basis for real-world decisions.

## Data

The project uses the Titanic: Machine Learning from Disaster dataset, provided through Kaggle.

### Raw data

The original dataset contains two CSV files, stored in data/raw/:

- `train.csv`: 891 passenger records and 12 columns, including the `Survived` target.

- `test.csv`: 418 passenger records and 11 columns. It does not contain the `Survived` target.

Each row represents one passenger. The 891 labelled passengers in `train.csv` are divided into a development set (70%, 623 passengers) and a held-out test set (30%, 268 passengers) using stratified sampling. The development set is used for exploratory data analysis and model development, including five-fold stratified cross-validation. The held-out set is reserved for final model evaluation. Kaggle's original `test.csv` remains separate and is used to generate predictions for the 418 passengers whose survival outcomes are unknown.

### Processed data

The analysis report cleans and transforms the raw data and saves the resulting files in `data/processed/`:

- `train_processed.csv`: processed development data, containing 623 passengers, engineered features, `PassengerId`, and `Survived`.

- `test_processed.csv`: processed Kaggle test data, containing 418 passengers, the same engineered features and `PassengerId`, but no `Survived` column.

- `selected_features.txt`: the five features selected for the initial modelling analysis using correlations with survival in the development data. Feature selection is also performed independently within each cross-validation training fold.

- `test_predictions.csv`: predicted survival outcomes and probabilities for the 418 passengers in Kaggle's unlabelled test dataset.

Missing values are handled using values learned from the development data and then applied to the held-out and Kaggle test datasets. Age is imputed using the median age for the passenger's title, missing embarkation ports are filled using the most common port, and missing fares are filled using the median fare for the passenger's class. Cabin information is represented by an indicator showing whether a cabin was recorded. Missing-value indicators are also retained where appropriate. Within cross-validation, imputation is fitted separately on each training fold to prevent information from the validation fold influencing the imputed values.

The raw and processed datasets are generated by the analysis workflow and are not committed to the repository.

## How to run the analysis

The project uses Python, [uv](https://docs.astral.sh/uv/) to manage the Python environment, and [Quarto](https://quarto.org/) to render the report. Install [uv](https://docs.astral.sh/uv/getting-started/installation/), Python 3.12 or newer, and [Quarto](https://quarto.org/docs/get-started/) first. These tools are installed separately.

From a terminal, clone the repository and enter its directory:

```sh
git clone https://github.com/UBC-MDS-2026-27/DSCI-522-Group-39-Repository.git
cd DSCI-522-Group-39-Repository
```

Set up Kaggle API credentials
The Titanic dataset is hosted on Kaggle. Before running the analysis:

- Create or sign in to your Kaggle account.
- Open the Titanic competition page and join the competition.
- Visit Kaggle API settings.
- Create a Legacy API Key and download the kaggle.json file.
- Place the downloaded file in the .kaggle directory inside your home directory.

macOS / Linux

```sh
mkdir -p ~/.kaggle
mv ~/Downloads/kaggle.json ~/.kaggle/kaggle.json
chmod 600 ~/.kaggle/kaggle.json
```

Windows PowerShell

```sh
New-Item -ItemType Directory -Force "$HOME\.kaggle"
Move-Item "$HOME\Downloads\kaggle.json" "$HOME\.kaggle\kaggle.json"
```

Keep your API credentials private. Do not commit kaggle.json to the repository or share it with others.

Create the project environment from the committed dependency files:

```sh
uv sync --locked
```

Render the Quarto project from its root directory:

```sh
uv run quarto render
```

Rendering requires an internet connection if the analysis needs to download the Kaggle dataset. If the raw dataset files are already present, the workflow skips the download.
